Запуск системы – docker compose up -d, проверка статуса
контейнеров, INFO replication показывает 2 реплики.

> docker-compose up --build -d
> docker-compose logs -f notification-consumer
> docker exec gamehub-redis-master redis-cli INFO replication


Работа приложения – создание профиля, обновление уровня,
добавление очков в лидерборд, получение топ-10, добавление
достижений, пересечение достижений.

> ./prepare_check_data.sh
> python3 dz1_check.py


Кеширование – первый запрос профиля (cache miss), повторный
(cache hit), проверка TTL.

Очередь уведомлений – при обновлении профиля уведомление
появляется в потоке; потребитель читает и подтверждает.

> Показать терминал


Защита от split-brain – покажите, что при docker pause на всех репликах
мастер начинает отклонять записи (ошибка min-replicas-to-write).
Затем восстановите реплики (docker unpause).

> docker pause gamehub-redis-replica-1 gamehub-redis-replica-2
> sleep 12
> docker exec gamehub-redis-master redis-cli SET splitbrain:test value
> docker unpause gamehub-redis-replica-1 gamehub-redis-replica-2
> sleep 12
> docker exec gamehub-redis-master redis-cli INFO replication
> docker exec gamehub-redis-master redis-cli SET splitbrain:test value


Отказоустойчивость (Sentinel) – остановка мастера (docker stop redis-
master), ожидание ~15 секунд, проверка, что Sentinel переключил
мастера на реплику, и приложение продолжает работать.

> docker exec gamehub-redis-sentinel-1 redis-cli -p 26379 SENTINEL get-master-addr-by-name mymaster
> docker stop gamehub-redis-master
> sleep 15
> docker exec gamehub-redis-sentinel-1 redis-cli -p 26379 SENTINEL get-master-addr-by-name mymaster
> Проверить на фронтенде, что операция записи продолжает работать
> docker start gamehub-redis-master
> sleep 10
> docker exec gamehub-redis-master redis-cli INFO replication
